# Спецификация design-game v4

## Цель

Скилл ведёт игру от идеи до диздока по стадиям 0–7 метода Шелла. Человек ставит его по ссылке на GitHub в Claude Code или Codex. Модель идёт по пайплайну и не своевольничает, скилл занимает мало контекста.

## Пайплайн

- Стадии: 0 сердце опыта, 1 концепт и тетрада, 2 механики, 3 баланс, 4 опыт и интерфейс, 5 нарратив и мир (осознанный пропуск со статусом `SKIP`), 6 плейтест, 7 релиз.
- Круг стадии: входящие владельца → подбор линз → роль стадии → зонд при риске → проверка `--before-keeper` → сверка хранителя → статус `GATE` → карточка гейта → решение владельца.
- Правило цикла: на каждом гейте «какая проблема теперь, какой риск самый крупный» — дальше или возврат на любую стадию. Реестр рисков — с первой стадии.
- Восемь фильтров на каждом гейте; девятый — для рекламных и обучающих игр.
- Гейт аудитории в конце стадии 0: без анкеты аудитории (`check_stage.py --audience`) агент-игрок и интервью не запускаются. Вопросы интервью проверяет хранитель по правилам `templates/INTERVIEW-BASE.md` — это смысловая проверка, скриптом её не сделать.
- Вход «продолжим игру»: раскладка досоздаёт недостающее, Библия показывает состояние, работа идёт с первой незакрытой стадии.

## Как исключены вольности модели

| Шаг | Скрипт | Что делает вместо модели |
|---|---|---|
| Раскладка игры | `init_game.py` | папки и файлы из шаблонов, существующее не трогает |
| Набор линз | `pick_lenses.py` | ядро стадии, линзы по паспорту, симптомы, вопросы владельцу — по `stages.json`; ошибка паспорта — код 2 |
| Готовность стадии | `check_stage.py` | шапка, разделы шаблона, вопросы, журнал линз по набору, статус знания, `[!owner]`, заглушки, формат вердикта хранителя; на стадии 0 — стержень и анкета; `--audience` — готовность анкеты перед агентом-игроком |
| Ответы владельца | `inbox.py` | необработанные `[!owner]` и открытые вопросы |
| Гейт | `gate.py` | карточка только после проверки и сверки хранителя; `--accept` — стадия в OK, `--return M` — возврат, оба со строкой в журнале решений |
| Библия | `build_bible.py` | единственный документ «прочитать всё» |
| Деньги | `money.py` | окупаемость: модель в арифметике ошибается |

## Контекст

`SKILL.md` короткий, остальное грузится по месту: шаги и шаблон текущей стадии, роль, стержень игры и линзы из `pick_lenses.py`. Без тегов на стадию идёт 4 линзы ядра, хранителю на гейте — ещё 8 сквозных. Линзы, вшитые в шаблон, текстом не грузятся: их вопросы стали разделами.

## Форматы

- Паспорт игры — блок «ключ: значение» в разделе «## Паспорт игры» стержня: масштаб, теги, заказчик, соавторы, зрители, новая технология, режим, прото.
- Шапка файла стадии: управляющая идея, стадия, агент, статус (`TODO`, `DRAFT`, `GATE`, `OK`, `BLOCK`, `SKIP`, `ЖДЁТ ВЛАДЕЛЬЦА`), дата, строка «Линзы стадии».
- Вопросы владельцу — `Q-NN.k` с рекомендацией; комментарии — `[!owner]` → `[!owner-ok]` и ответ `[!agent]`; решения auto — `[!auto]`.
- Вердикт хранителя — `OK`, `DRIFT` (закрыть с переносом), `BLOCK` (возврат), `ЖДЁТ ВЛАДЕЛЬЦА`.
- Статус знания — `факт`, `вкус владельца`, `гипотеза`, `проверено`.

## Решения по умолчанию

- Колода: 113 линз Шелла своими словами, 93½ из третьего издания (вопросы наши, с книгой не сверены — её текста в нашем разборе не было), две наши линзы с пометкой «не Шелл».
- Код зонда в сборку не переносится — наше правило, строже книги; константы и выводы переносятся.
- Безопасность детей в играх с общением: по умолчанию без свободного текста и без контакта с незнакомцами; свободный чат детей — только по слову владельца.
- Агент-игрок — на любом зонде после гейта аудитории; его выводы — гипотезы.
- База — на русском; английская база — отдельный этап.
