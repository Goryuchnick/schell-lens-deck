# CONSISTENCY — сверки хранителя · {{Название игры}}

> Управляющая идея: **{{одно предложение из 00-heart/CONTROLLING-IDEA.md}}**

После каждой стадии `gd-keeper` пересматривает все стадии, а не только последнюю: решение на поздней стадии задним числом может спорить с ранней. Записи только добавляются, старые не правятся — история дрейфа видна целиком.

Вердикт — одно из четырёх значений, его читают `scripts/build_bible.py` и карточка гейта:

- `OK` — стадия держится за управляющую идею и не спорит с другими стадиями;
- `DRIFT` — есть дрейф или противоречие, правки точечные, стадию можно закрыть с переносом вопросов;
- `BLOCK` — серьёзный дрейф или противоречие, нужен возврат на стадию, указанную в записи;
- `ЖДЁТ ВЛАДЕЛЬЦА` — остался вердикт, который ставит только владелец: первый фильтр, линза 111 «Ответственность», всё, что уходит наружу от его имени.
