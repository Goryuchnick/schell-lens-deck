# stage-map — Карта СТАДИЯ → ЛИНЗЫ

> **Источник истины** для оркестратора (`SKILL.md`) и стадийных агентов (`gd-*`): какие линзы тянуть на каждой стадии, что остаётся при урезании под масштаб, и когда дёргать `gd-prototyper`.
> Точные формулировки фокус-вопросов — в [`lenses.md`](./lenses.md). Здесь — только маппинг и правила.
> Дисциплина зонда (формы, «один вопрос», `disposable`) — в [`schell-prototyping.md`](./schell-prototyping.md).

---

## Как читать эту карту

Каждая стадия описана блоком:

- **Цель / артефакт** — что на выходе.
- **Агент** — кто пишет (контракт §6 SPEC).
- **Линзы стадии** — полный набор для `large`.
- **Scale-урезание** — что остаётся для `mini / small / medium / large`. Линзы, помеченные **🔒 ядро**, не вырезаются никогда (на любом масштабе).
- **Risk-gate** (только стадии 2 / 3 / 6) — когда поднимать `gd-prototyper`.

**Инвариант (любой масштаб):**
> Перед применением линз стадии агент **обязан** прочитать `CONTROLLING-IDEA.md` и держать управляющую идею как эталон. Любой элемент, не усиливающий управляющую идею, — кандидат на вырезание (линза Unification, вшитая в процесс). После стадии — всегда `gd-keeper`, на любом масштабе.

**Легенда scale-колонок:**

| scale | смысл | стадии | глубина линз |
|---|---|---|---|
| `mini` | миниигра на 5 минут, один экран | 0–2, 4, 6 (3/5/7 ужаты или пропущены) | 3–4 ядровые линзы на стадию |
| `small` | джем-игра, узкий вертикальный срез | 0–4, 6, (7 кратко) | ядро + 1–2 расширения |
| `medium` | полноценная инди-игра | 0–7 (5 опционально) | почти полный набор |
| `large` | AAA-концепт / большой проект | 0–7, все линзы | полный набор |

> ✅ — линза включена · ➖ — вырезана/опциональна на этом масштабе · 🔒 — ядро (никогда не вырезается).

## Advergame / serious-game overlay

> Применяется **только** если в брифе тип игры = `advergame / serious` (продаёт продукт / меняет поведение / обучает). Для `entertainment` — пропускается, обычный флоу не трогается.

Для рекламных/обучающих игр три линзы — **Secret Purpose** + **Honest Claim** + **Responsibility** — вытягиваются вперёд из стадии 7 и работают сквозь весь пайплайн:

- **Стадия 0 (бриф):** Secret Purpose фиксируется обязательно (настоящая внеигровая цель) + truth-ограничения → секция «Secret Purpose и Truth-ограничения» в `CONTROLLING-IDEA.md`.
- **Стадия 3 (ограничивается):** любое число, которое игра выносит **наружу** как реальное обещание (экономия ₽/%/время), обязано иметь **источник** либо явную пометку **«иллюстративное»**. Выдуманное число-claim без источника/пометки = стоп, эскалация пользователю (см. `gd-balance`).
- **Стадия 7 (обязательна, не skippable):** даже на `mini`/`small` Honest Claim + Responsibility прогоняются — реклама не выкладывается «по ссылке» без проверки правдивости claim'ов.

`gd-keeper` ловит «реальный claim наружу без источника/ограничения/иллюстративной пометки» как `DRIFT (Responsibility / Honest Claim)`.

### Risk-gate → `gd-prototyper`

Поднимать зонд на стадии 2, если есть рискованное допущение про **структуру решений или приятность ядра**, которое дешевле проверить, чем спорить на бумаге. Триггеры:

- неясно, **приятно ли ядро тискать** (Lens of the Toy не закрывается рассуждением) → зонд-«игрушка»;
- core loop держится на **недоказанном допущении** про петлю «действие → результат → мотив»;
- спор «выбор значимый или ложный» нельзя разрешить логикой.

**Форма по умолчанию (лестница §2.5 SPEC):** структура решений / петля → бумажный или текстовый прото / ASCII-сим (код не нужен). Только если риск именно в **ощущении / тайминге / управлении** — веб-зонд (TS + Phaser/Canvas, запуск через Playwright).
**Один вопрос на зонд**, помечается `disposable`, вывод → `LENS-LOG.md` + раздел GDD.

> `mini`: risk-gate включается **только** под вопрос «ядро приятно тискать?» — остальные допущения для миниигры обычно дешевле просто принять.

### Risk-gate → `gd-prototyper`

Стадия 6 — **самая частая точка зонда**: здесь проверяется реальная играбельность. Поднимать `gd-prototyper`, если:

- режим брифа = `docs + прото-зонды` **и** есть открытый вопрос, который закрывается **только живой игрой** (ощущение, тайминг, читаемость, «весело ли вообще»);
- предыдущие стадии оставили в `LENS-LOG` ответы со статусом «пока открыт», требующие плейтеста;

**Один вопрос на зонд**, `disposable`. «Вопрос провалился» = **успех зонда** → возврат стадийному агенту на пересборку решения (BLOCK-логика §7 SPEC).

## Подбор линз: проактивный и реактивный (v2, §12 SPEC)

> **Проблема v1:** scale-подсписок резал линзы по размеру проекта, не по риску/категории → нужные линзы не доходили (пример: `Honest Claim` обрезался mini-подсписком, хотя advergame-риск был явным).

### Правило подбора линз на стадии (проактивный режим)

Набор линз для стадии = **обязательное ядро стадии** + **foundational-линзы** + **pull по `categories`/рискам игры** из `lens-index.json`.

`scale` по-прежнему управляет **глубиной** (сколько вопросов прорабатывается), но **не урезает линзу**, если она релевантна категории/риску игры.

Пошагово:
1. Взять обязательное ядро стадии (🔒 из этой карты) — всегда.
2. Добавить все **foundational**-линзы как постоянных кандидатов (Essential Experience, The Toy, Flow, Curiosity, Fun, Holographic Design, Unification, Elemental Tetrad, The Player, Interest Curve, The Interface, Feedback, The Loop, The Playtest, Challenge, Balance).
3. Из тегов игры (из брифа) → найти совпадения по `categories` в `lens-index.json` → добавить совпавшие линзы, даже если scale = `mini`.
4. Показать дизайнеру только отобранный набор (ядро + foundational + pull). Полная колода — по запросу.

**Пример:** игра `mini` + тип `advergame` → `Honest Claim`, `Responsibility`, `Secret Purpose` вытягиваются в стадии 3 и 7, несмотря на `mini`-масштаб.

**Теги игры** агент инферит из брифа (тип игры, платформа, аудитория, монетизация), человек подтверждает. Возможные теги: `advergame`, `multiplayer`, `narrative`, `competitive`, `kids`, `real-money`, `spatial`, `economy`.

### Реактивный подбор — «застрял-режим» (toolbox Шелла)

Когда дизайнер говорит «что-то не так», «бесит», «не пойму почему не работает» — оркестратор:

1. Ловит **реплику дискомфорта** (симптом).
2. Ищет симптом в поле `diagnoses` в `lens-index.json`.
3. Подаёт **2–3 линзы-кандидата** с их ключевым вопросом.
4. Предлагает: «прогоним дизайн через эту линзу?» — решает человек.

Агент **подаёт линзу в руку**, не навязывает. Полная таблица симптомов → линз:

| Симптом | Линзы-кандидаты |
|---|---|
| «скучно» | Fun, Flow, Interest Curve, Curiosity |
| «нечестно» | Fairness, Balance, Skill vs Chance |
| «не понимаю что делать» | Goals, The Interface, Feedback, Accessibility |
| «нет напряжения» | Interest Curve, Flow, Challenge, Anticipation |
| «выборы фальшивые» | Meaningful Choices, Freedom, Triangularity |
| «не цепляет» | Curiosity, Fun, Inherent Interest, Emotion |
| «теряюсь в пространстве» | Space, Indirect Control, Feeling of Presence |
| «числа выдуманы / claim без источника» | Honest Claim, Responsibility, Endogenous Value |
| «механика и история тянут в разные стороны» | Unification, Holographic Design, The Story |
| «игрок бросает» | Curiosity, Motivation, Interest Curve, The Loop |
| «монетизация вредит опыту» | The Profit, Responsibility, Endogenous Value |
| «персонаж неживой» | Character, Inner Contradiction, Character Transformation |

Исходник данных — `lenses/lens-index.json` (поле `diagnoses`). Оркестратор читает его машинно при маршрутизации застрял-режима.
