# models.md — резолв тира модели в конкретную модель по тулу

> **Стержень.** Этот документ обслуживает [управляющую идею](../templates/CONTROLLING-IDEA.md): модель под роль подбирается так, чтобы каждый субагент сильнее тянул на тему игры, а не «крутил токены вхолостую». Тир — это про требуемую глубину мышления роли, не про бренд модели.

Core помечает роль **тиром** (`reasoning-heavy | balanced-creative | mechanical`), а не конкретной моделью. Конкретику подставляет оркестратор под тул из таблицы ниже — это держит [portable design layer](../docs/SPEC.md) движко- и тул-агностичным.

---

## Тиры

| Тир | Когда применять | Кто на нём (роли) |
|---|---|---|
| **reasoning-heavy** | концепт, баланс, keeper — критический аудит, числа, дрейф от управляющей идеи | `gd-keeper`, `gd-concept`, `gd-balance` |
| **balanced-creative** | механики, опыт, нарратив, плейтест, релиз, зонды — креатив + дисциплина | `gd-mechanics`, `gd-experience`, `gd-narrative`, `gd-playtest`, `gd-release`, `gd-prototyper` |
| **mechanical** | сборка прото-скаффолда, питч-вёрстка, форматирование — без рассуждений | вспомогательные проходы (вёрстка, формат) |

---

## Таблица ТИР → МОДЕЛЬ по тулу

Значение из соответствующей колонки идёт **дословно** в поле `model:` YAML-фронтматтера субагента.

| Тир | Claude Code | Cursor | Antigravity |
|---|---|---|---|
| **reasoning-heavy** | `opus` | `claude-opus-4.x` | `Gemini 3 Pro` (альт. `Claude Opus 4.6`) |
| **balanced-creative** | `sonnet` | `inherit` (или `claude-sonnet-4.x`) | `Claude Sonnet 4.6` (альт. `Gemini 3 Pro`) |
| **mechanical** | `haiku` | `fast` | `Gemini 3 Flash` (альт. `GPT-OSS`) |

> Словарь `model` различается по тулам — это единственное, что расходится при переносе набора между ними. Тело субагента (роль, контракт, линзы) остаётся одним и тем же.

---

## Правило оркестратора

**При генерации субагентов под конкретный тул оркестратор берёт тир роли (из [контракта субагентов в SPEC §6](../docs/SPEC.md)) и подставляет значение из колонки этого тула в поле `model` фронтматтера.**

```yaml
---
name: {{имя-субагента}}        # напр. gd-keeper
description: {{краткая роль}}
model: {{значение из таблицы}}  # тир → колонка тула; напр. reasoning-heavy + Claude Code → opus
tools: {{инструменты роли}}     # напр. Read, Grep, Glob, Write, Edit
---
```

Под какой тул генерируем — берётся из активного адаптера:

| Целевой тул | Колонка таблицы | Куда кладём субагент |
|---|---|---|
| Claude Code | `Claude Code` | `.claude/agents/{{имя}}.md` |
| Cursor | `Cursor` | `.cursor/agents/{{имя}}.md` (Cursor также читает `.claude/agents/`) |
| Antigravity | `Antigravity` | `.agents/agents.md` (транскрипция) |

### Где есть выбор (альт.)

Если в колонке Antigravity указана альтернатива — по умолчанию первое значение; второе ставим, когда `{{предпочтение пользователя}}` явно за другого вендора (например, держать критический аудит на Claude Opus вместо Gemini Pro). Фиксируй выбор в самом адаптере, чтобы он был один на весь набор, а не вразнобой по агентам.

## Пример резолва

Роль `gd-balance`, тир **reasoning-heavy**, генерим под Cursor → в `model` уходит `claude-opus-4.x`:

```yaml
---
name: gd-balance
description: Баланс, экономика, кривые сложности; сверяется с управляющей идеей
model: claude-opus-4.x
tools: Read, Write, Edit, Bash
---
```
