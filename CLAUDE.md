# CLAUDE.md — gamedesign

Инструкции для сессий Claude Code в этой папке.

## Что это

Пайплайн **проектирования игры по линзам Джесси Шелла** («The Art of Game Design: A Book of Lenses») — через Claude Code, без отдельного LLM-сервиса. Все вызовы к LLM — это ты сам и субагенты `gd-*`. Ведёт от идеи до релиза по стадиям 0–7.

Архитектурный близнец `neurowriter/`: глобальный скилл-оркестратор + субагенты-стадии + Markdown-артефакты, статус каждой стадии `OK | BLOCK`. Спроектирован **переносимым** между тулзами (Claude Code / Cursor / Antigravity) — см. `adapters/`.

Полная спецификация — [docs/SPEC.md](docs/SPEC.md).

## Когда работаешь над игрой

1. Запусти `/design-game` (или см. `.claude/skills/design-game/SKILL.md`). Он спросит бриф и поведёт по стадиям.
2. Артефакты игры пишутся в `<game-path>/` (путь спрашивается в брифе — `games/<slug>/`, route в сайте, отдельная папка).
3. Стержень — `CONTROLLING-IDEA.md`. Без согласованной управляющей идеи стадии не запускаются.

## Структура

```
gamedesign/
  CLAUDE.md                      ← этот файл
  docs/SPEC.md                   ← спецификация скилла
  lenses/
    lenses.md                    ← библиотека ~90 линз Шелла (имя + фокус-вопросы)
    stage-map.md                 ← СТАДИЯ → ЛИНЗЫ + scale-урезание + risk-gate (источник истины)
    schell-prototyping.md        ← дисциплина прото-зонда по Шеллу
    models.md                    ← тир → модель по тулу
  templates/                     ← CONTROLLING-IDEA, LENS-LOG, GDD, CONSISTENCY, PITCH, PROTOTYPE-PROBE
  adapters/                      ← claude-code / cursor / antigravity
  .claude/agents/gd-*.md         ← 9 субагентов-стадий
```

## Pipeline по умолчанию

```
бриф → CONTROLLING-IDEA → [для стадий 1..7:
   стадийный агент → (risk-gate → gd-prototyper) → gd-keeper → BLOCK? петля : дальше]
→ GDD.md + PITCH.md (+ играбельный билд, если веб-зонды)
```

Стадии 0 Сердце опыта · 1 Концепт+тетрада · 2 Механики · 3 Баланс · 4 Опыт/интерфейс · 5 Нарратив *(skippable)* · 6 Плейтест · 7 Релиз.

## Жёсткие правила

- **Управляющая идея — стержень.** Живёт в шапке каждого артефакта; каждый агент сверяет с ней решения (линза Unification). На `mini` она короче, но обязательна.
- **Правило петли.** После КАЖДОЙ стадии — `gd-keeper` (обратная сверка всех предыдущих). Не пропускать.
- **Живой журнал.** Ответы на линзы копятся в `LENS-LOG.md`, могут висеть `open`. Не заставляй отвечать на всё сразу.
- **Engine-agnostic ядро.** Движок — только в опоре «Технология», стадии «Прототип», «Релиз». Не тащи его в стадии 0–1.
- **Прото = одноразовый зонд, не старт разработки.** Один вопрос на зонд, самая лёгкая форма (бумага/таблица/ASCII/веб), помечен `disposable`. Привязываться к коду зонда запрещено. См. `lenses/schell-prototyping.md`.
- **Один растущий `GDD.md` = один писатель.** Стадии последовательно. Параллелить только разные игры.
- **Не правь `lenses/*` и `templates/*` без явного запроса** — это источник истины скилла.

## Масштаб (scale)

`mini` (5 минут, один экран) / `small` (джем) / `medium` (инди) / `large` (большой проект). Управляет набором стадий и глубиной линз (см. `lenses/stage-map.md`), но не наличием управляющей идеи и не отменяет `gd-keeper`.

## Среда

- Windows / Git Bash. `python` (не `python3`).
- Веб-зонды (`gd-prototyper`): TS + Phaser/Canvas, запуск через Playwright MCP — только когда вопрос про ощущение/тайминг. Иначе безкодовые формы.

## Что не делать

- Не свёртывать стадии в один проход — каждая стадия создаёт свой раздел GDD + записи в LENS-LOG.
- Не писать диздок без `CONTROLLING-IDEA.md`.
- Не привязываться к коду прото-зонда.
- Не звать внешние LLM из скриптов — генерация только через тебя/субагентов.
